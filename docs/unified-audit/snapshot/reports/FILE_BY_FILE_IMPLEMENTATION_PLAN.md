**Evidence:** S = source-verified code/declaration; D = upstream documentation/policy claim; M = actually measured; P = proposed; H = hypothesis. A manifest, tool schema, doc page or test filename does not prove successful execution. Status describes Zenith parity, not whether a reference project works.

**No destinations in this plan have been created or edited by the audit.** The [machine-readable plan](../evidence/file-by-file-plan.json) is authoritative for all 421 unique proposed destinations, their dependencies, acceptance behavior, source feature IDs, blockers, branch existence and rollback instructions. 158 entries are test destinations. Names and partitioning are review proposals; they are not an instruction to create empty modules.

Review base: main e6963d9; pilot PR19 44d55d2 and reasoning PR18 ac989d8 are unmerged. Reconcile overlapping owners after audit approval; preserve both branches.. Resolve PR18 planning/verification ownership and PR19 policy/task/migration ownership first. Keep public Agent.generate/stream and provider constructors working. Apply additive changes with default-off flags, not wholesale replacements. Preserve the checksum of shipped migration V1 and introduce versioned successors. Canonical channel/provider modules are separate review units, not an excuse for wrappers that lack real transport behavior.

Dependencies are group prerequisites in [the graph](DEPENDENCY_GRAPH.md). A test file implements its stated contract; test fixtures may simulate failures, but production transport acceptance needs a real supported backend. File rollback means disabling the relevant capability and retaining durable data; it does not mean deleting user history or reverting a live database blindly. Read [deployment/rollback](DEPLOYMENT_AND_ROLLBACK_PLAN.md) for sequencing.
