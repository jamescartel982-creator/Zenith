## Supported public interfaces

### WebSocket control plane

Wire version is **4**, general client minimum **4**, node/probe minimum **3**: [packages/gateway-protocol/src/version.ts:2](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/packages/gateway-protocol/src/version.ts#L2). Published-source `@openclaw/gateway-client` and `@openclaw/gateway-protocol` packages are 2026.10.7 and declare Node>=22.19.0. That client requirement does not relax the root Gateway's **Node >=24.22.1 <25 or >=26.12.1; pnpm12.15.0** requirement: [packages/gateway-client/package.json:1](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/packages/gateway-client/package.json#L1), [packages/gateway-protocol/package.json:1](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/packages/gateway-protocol/package.json#L1), [package.json:2517](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/package.json#L2517). Registry package availability was not tested. The clients guide contains an older 2026.8.1 install example, so pin/test the installed client and gateway deliberately: [docs/gateway/clients.md:1](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/clients.md#L1).

The Gateway emits `connect.challenge`; device clients sign the nonce and challenge timestamp, declare supported min/max protocol, a documented client identity, role and requested scopes, then consume effective authorization in `hello-ok`. Requested scopes are not a grant. The request/response/event shapes and limits come from public package schemas, not guessed Python payloads: [docs/gateway/protocol/handshake.md:21](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/protocol/handshake.md#L21), [packages/gateway-protocol/src/schema/frames.ts:34](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/packages/gateway-protocol/src/schema/frames.ts#L34), [packages/gateway-protocol/src/schema/frames.ts:174](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/packages/gateway-protocol/src/schema/frames.ts#L174), [packages/gateway-client/src/client.ts:290](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/packages/gateway-client/src/client.ts#L290).

Typical chat clients need operator.read/write; approvals, pairing, questions and admin scopes are distinct responsibilities, not defaults for every bridge session. Persist paired tokens for the correct gateway/device/role; effective scopes are the live socket authority. Never embed a Gateway bootstrap/shared secret in a model prompt: [docs/gateway/clients.md:55](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/clients.md#L55), [docs/gateway/protocol/auth.md:30](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/protocol/auth.md#L30), [src/gateway/method-scopes.ts:1](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/src/gateway/method-scopes.ts#L1).

`hello-ok.features.methods` is conservative discovery rather than an exhaustive list or proof of permission: [docs/gateway/protocol/rpc-methods.md:16](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/protocol/rpc-methods.md#L16). Python may implement this public protocol, but compatibility needs real wire tests; alternatively use a separately configured thin client helper pinned to the published package. Neither route requires patching Gateway internals.

### Tasks, sessions, retry and cancellation

Native methods include sessions.list/get/describe/create/send, chat.history/send/abort and sessions.abort. `agent` and `agent.wait` are real native agent run handlers, with native visibility and session authorization. Retain native IDs instead of reconstructing them: [docs/gateway/protocol/rpc-session-control.md:1](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/protocol/rpc-session-control.md#L1), [src/gateway/server-methods/agent.ts:85](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/src/gateway/server-methods/agent.ts#L85), [src/gateway/server-methods/sessions-abort.ts:1](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/src/gateway/server-methods/sessions-abort.ts#L1).

`chat.send.idempotencyKey` is explicitly documented as session-bound durable submission identity while its user row/input receipt remains. Same key + different content conflicts. A deleted/replaced session is not the same replay domain. Acknowledgment confirms acceptance, not task completion or automatic restart recovery; client wait timeout alone does not cancel accepted work. Preserve the same physical session on retry, follow terminal events/status, and use native cancel methods before making a failover decision: [docs/gateway/protocol/rpc-session-control.md:20](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/protocol/rpc-session-control.md#L20), [docs/gateway/protocol/rpc-session-control.md:100](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/protocol/rpc-session-control.md#L100).

The additive bridge needs one selected backend per admitted task, original submission identity, native session/run mapping and explicit uncertain-outcome state. Never blindly resend an accepted/uncertain effect to Hermes under a new key. Other RPCs keep their own contracts; do not generalize chat.send idempotence to all tools/schedules.

### HTTP compatibility exposes an agent, not raw foundation inference

Default-off native Chat Completions and independently enabled Responses share the Gateway port. They execute the OpenClaw agent with native policies. `/v1/models` lists agent targets such as `openclaw/default`, not underlying foundation models. The actual Zenith model provider must be configured separately. Embeddings are another separately supported capability, not implied by a language tokenizer: [docs/gateway/openai-http-api.md:8](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/openai-http-api.md#L8), [docs/gateway/openai-http-api.md:78](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/openai-http-api.md#L78), [src/gateway/openai-http.ts:364](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/src/gateway/openai-http.ts#L364), [src/gateway/openresponses-http.ts:94](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/src/gateway/openresponses-http.ts#L94).

**Critical boundary:** shared token/password HTTP auth is documented full operator/owner access and ignores a narrower bearer-declared x-openclaw-scopes. A Zenith per-user header over one owner secret is not native least privilege. Prefer genuinely paired/scoped WS identities, or an explicitly configured/tested identity-bearing trusted proxy with native policies. Keep ingress private and authenticated: [docs/gateway/openai-http-api.md:41](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/openai-http-api.md#L41), [docs/gateway/openresponses-http-api.md:23](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/gateway/openresponses-http-api.md#L23).

The bridge cannot impose Zenith RBAC on every internal native tool call merely by authenticating task ingress. Original native UIs retain original authorization semantics. An isolated, explicitly created integration profile plus native tool policy/approval and OS sandbox/network limits can bound bridge work without altering original profiles. If an unsupported native enforcement gap requires patching, report it and request the user's mandated approval.

### Configuring Zenith as the underlying model

Use documented `models.providers` with exact verified baseUrl/API/model metadata; choose default provider/model via `agents.defaults.model.primary`. Provider metadata must describe Zenith's actual measured context, modalities and tool behavior, not borrow another catalog model's capability claims. Aliases/default-model metadata does not itself restrict model overrides. Native model policy is separate: [docs/concepts/model-providers/custom-providers.md:10](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/concepts/model-providers/custom-providers.md#L10), [docs/concepts/model-providers/custom-providers.md:58](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/concepts/model-providers/custom-providers.md#L58).

A dedicated authenticated Zenith-compatible inference adapter remains a proposal pending the parent audit's endpoint inventory and the user's required approval. Do not assume Zenith's custom chat endpoint is compatible, loop an OpenClaw agent API back into its own provider, silently swap model weights, or claim tool/multimodal support from an alias. New integration configs must be separate files/profiles rather than edits to protected original configs.

## 24/7 service ownership and platform limits

Native supported commands: `openclaw gateway install/start/stop/restart/uninstall`. Linux systemd, macOS launchd and Windows Task Scheduler semantics differ. Preserve installed definitions and native ownership checks. Explicit Linux stop suppresses Restart=always until a later start; uninstall preserves native config/plugins/sessions/workspaces. Do not add a competing supervisor that restarts a deliberately stopped original instance. An independently named integration deployment must be explicitly owned: [docs/cli/gateway/service.md:16](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/cli/gateway/service.md#L16), [docs/cli/gateway/service.md:76](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/docs/cli/gateway/service.md#L76), [src/daemon/systemd.ts:1](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/src/daemon/systemd.ts#L1), [src/daemon/launchd.ts:1](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/src/daemon/launchd.ts#L1), [src/daemon/schtasks-control.ts:1](https://github.com/openclaw/openclaw/blob/2f5727b9c61c2ba9dccc3c880d9115f02cb8652f/src/daemon/schtasks-control.ts#L1).

24/7 availability requires an always-powered host, supported runtime/dependencies, private authenticated ingress/TLS, bounded model admission, distinct native durable volumes, disk/backup/restore, health/readiness, restart reconciliation, monitoring and a real soak test. A transient execution environment or CPU smoke cannot establish it. Devices, OS permissions, messaging accounts and provider credentials remain per-integration prerequisites.
