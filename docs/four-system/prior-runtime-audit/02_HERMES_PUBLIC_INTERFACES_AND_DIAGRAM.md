## Public agent HTTP interface (S/D, not live tested)

[gateway/platforms/api_server.py:1565](https://github.com/NousResearch/hermes-agent/blob/d05095663342556788cf2a198bfa7844cc7968ab/gateway/platforms/api_server.py#L1565) registers the native agent APIs. [The extracted route inventory](../evidence/hermes-http-route-inventory.json) retains literal registered methods/paths from the facade and run/room helpers; conditional/extension registrations still require runtime discovery. Core contracts include `/v1/models`, `/v1/capabilities`, `/v1/chat/completions`, `/v1/responses`, native sessions, `/v1/runs` lifecycle and `/api/jobs` schedules. These return/execute Hermes agent work; they do not expose raw Zenith foundation inference.

Native documented enablement is API_SERVER_ENABLED plus a private API_SERVER_KEY in a separately created profile; start via `hermes gateway`, default API loopback8642. Do not reuse the documentation's sample key. Native profile auth and routing are owned by [gateway/platforms/api_server.py:1415](https://github.com/NousResearch/hermes-agent/blob/d05095663342556788cf2a198bfa7844cc7968ab/gateway/platforms/api_server.py#L1415) and [gateway/platforms/api_server.py:1799](https://github.com/NousResearch/hermes-agent/blob/d05095663342556788cf2a198bfa7844cc7968ab/gateway/platforms/api_server.py#L1799). Never pass arbitrary model/provider/base-url/key overrides through the bridge. Discover the configured agent alias; it may be profile-named rather than literally hermes-agent.

[website/docs/user-guide/features/api-server.md:79](https://github.com/NousResearch/hermes-agent/blob/d05095663342556788cf2a198bfa7844cc7968ab/website/docs/user-guide/features/api-server.md#L79) distinguishes canonical durable admission from legacy in-memory replay (including absent streaming deduplication). The bridge must require/verify the intended native capability/mode; it cannot generalize one Idempotency-Key to every mode. Keys are scoped to profile/credential; rotation changes replay identity. Ack/status/terminal events differ; an SSE HTTP200 or partial diagnostic text is not successful completion. Preserve native run/session/response IDs, consume native cancel/approval contracts, and reconcile uncertain effects instead of retrying under a new key/backend.

The API facade registers native job list/create/get/update/delete/pause/resume/run handlers. Use those public paths only when advertised/configured and authorized; never edit cron's private store from the bridge. Platform callback ingress has each platform's native signature verifier, not the agent API bearer. Session headers identify native conversations, not Zenith account authorization.

## ACP is complementary, not complete coverage

[acp_adapter/server.py:234](https://github.com/NousResearch/hermes-agent/blob/d05095663342556788cf2a198bfa7844cc7968ab/acp_adapter/server.py#L234) implements initialize/authenticate/new/load/resume/prompt/cancel. [acp_adapter/session.py:1](https://github.com/NousResearch/hermes-agent/blob/d05095663342556788cf2a198bfa7844cc7968ab/acp_adapter/session.py#L1) persists native history; [acp_adapter/permissions.py:128](https://github.com/NousResearch/hermes-agent/blob/d05095663342556788cf2a198bfa7844cc7968ab/acp_adapter/permissions.py#L128) mediates permission prompts. Public launch is `hermes acp`, `hermes-acp` or `python -m acp_adapter` after its managed ACP extra is installed. Stdout is the protocol stream, not a log channel. Protect a spawned stdio process with a dedicated OS/service identity and private handles; stdio itself is not remote bearer authentication.

[website/docs/user-guide/features/acp.md:40](https://github.com/NousResearch/hermes-agent/blob/d05095663342556788cf2a198bfa7844cc7968ab/website/docs/user-guide/features/acp.md#L40) explicitly excludes messaging delivery and cronjob management from the default editor toolset. Therefore ACP alone cannot cover the whole supplied diagram. Keep gateway/API/native UI paths as well; native platform_toolsets.acp and disabled toolsets stay native config. Client-supplied MCP specifications can contain commands/secrets and must not be forwarded from untrusted users; default bridge denies arbitrary MCP attachment until separately approved, without modifying original native profiles.

## Configuring the primary model

[website/docs/integrations/providers.md:714](https://github.com/NousResearch/hermes-agent/blob/d05095663342556788cf2a198bfa7844cc7968ab/website/docs/integrations/providers.md#L714) documents custom OpenAI-compatible inference. New integration profile model.default=`zenith`, provider=`custom`, base_url=<approved Zenith inference service>/v1, key_env=<private service key variable> is a proposed profile, not an edit to existing config. Use supported fields and correct secret scope; OPENAI_BASE_URL applies only to openai-api in this pin. Never point the provider at Hermes's own agent API or OpenClaw's agent API: that would recurse agent requests instead of serving foundation completions.
