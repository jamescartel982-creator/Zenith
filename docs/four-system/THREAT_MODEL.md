# Four-system threat model and operational boundaries

- **Identity:** separate service identities and secret stores; authenticate bridge↔native services and verify account/owner/MFA server-side. Raw model outputs and upstream descriptions never create grants. Do not confuse native requested scopes with effective scopes.
- **Isolation:** one dedicated profile/state directory per tenant/workflow, preserving native memories, sessions, cron, tools and subagents. No direct native SQLite edits or automatic memory/credential merge. Per-job TradingAgents processes prevent global config cross-talk.
- **Execution:** original full native risk graph always completes before a paper fill is considered. Paper-only ledger is explicitly new. Live mode/order endpoints/broker credentials are absent; egress denies broker/order APIs. Native agent shells/browser sessions must be separately isolated from any real brokerage account.
- **Reports:** validate UUID/account ownership, artifact roots and symlinks; preserve native decision/risk fields and REVIEW. Reports/news/tool descriptions are untrusted. Serve JSON/text by default and sandbox HTML. Logs contain ids, phases, durations and error categories, not prompts, secrets, full holdings or upstream exception dumps.
- **Delivery:** exact immutable report hash, account, channel and recipient approval; native OpenClaw send semantics and delivery queue; never infer authorization from a message body. Lost acknowledgement requires reconciliation, not duplicate delivery or failover to another channel.
- **Data:** separate analyst input snapshots from future settlement outcomes. Reject after-cutoff/undated historical evidence, record coverage gaps and model-knowledge-cutoff uncertainty. Preserve native withholding rather than inventing historical facts. Data licenses must allow archival/replay.
- **Recovery:** bounded retries only for safe reads; cancellation terminates the owned worker, records ambiguity and retains native checkpoints. Per-account queues, token/time/resource limits, source/config hashes and consistent backups; emergency stop prevents all new delegated work.
- **24/7:** an actual always-on host, private network, native supported service managers, owned volumes, health/readiness and measured crash/soak/backup tests are prerequisites. A Compose restart policy alone is not verified availability.
- **Rollback:** disable/drain the new bridge, preserve all native state, revoke only owned service tokens, stop only owned service units and restore pinned image/package versions. Original Zenith checkpoint/profile remains immutable. Native auto-updaters may stage new candidates but may not mutate the deployed pinned source tree.
